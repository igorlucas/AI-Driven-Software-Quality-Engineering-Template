# Requirements

Capture product intent separately from test cases. One requirement file may describe a business goal or feature, but keep acceptance criteria independently identified as `QA-nnn` and link them in `traceability/records.json`.

Use [template.md](template.md) for goals, scope, constraints, assumptions, open questions, dependencies, and acceptance criteria. Use [the AI requirement prompt](../ai/prompts/requirement-analysis.md) as a drafting aid; the requirement owner approves the result.
